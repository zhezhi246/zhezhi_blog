今天继续读 learncpp 的入门部分，主题从"变量到底是什么状态"一路走到"怎么写函数"。按 [学习指南](../learncpp-guide/) 的路线，这部分对应第 1–2 章。前半是完整笔记，后半是易错点。

## 一、完整笔记

### 1. 已初始化、赋值、未初始化

三个词说的是三件事：

- **已初始化**：对象在**定义的那一刻**就被赋予了确定的值。
- **赋值**：对象**定义之后**，再给它写入一个新值。
- **未初始化**：对象已经定义，但还没有被赋予具体的值。

```cpp
int a{};      // 已初始化（值初始化，值为 0）
int b;        // 未初始化
b = 5;        // 赋值
```

### 2. 未初始化变量的值

```cpp
int x;            // 未初始化
std::cout << x;   // 未定义行为
```

未初始化的局部变量**没有"默认值"**。读取它属于未定义行为，结果没有任何保证。口语上会把内存里残留的字节叫作"垃圾值"，但标准并不保证你读到的就是这些字节——编译器可以假设"不会有人读未初始化变量"，据此做任何优化。

用 `int x{};` 就没事，它是值初始化，值为 0。

### 3. 未定义行为与实现定义行为

- **Undefined behavior（未定义行为）**：标准对这个操作不做任何规定，程序行为不可预测。
- **Implementation-defined behavior（实现定义行为）**：标准要求实现必须选择一种行为，并写进文档。程序在该编译器上是确定的，换编译器可能不同，但仍然有保证。

| 情况 | 类别 |
| --- | --- |
| 读取未初始化的局部变量 | 未定义行为 |
| `sizeof(int)` 是 4 还是 8 | 实现定义 |
| 有符号整数溢出 | 未定义行为 |
| 多字符字面量 `'ab'` 的值 | 实现定义 |

### 4. 关键字与大小写

C++ 区分大小写：`int` 是关键字，`Int` 只是一个普通标识符。关键字不能拿来当变量名。

### 5. 命名规范

- 变量名通常以小写字母开头；由单个单词或缩写构成的变量名全小写，如 `count`、`id`。
- 函数名也以小写字母开头。
- 多个单词有两种常见写法：下划线分隔 `my_variable`，或首字母大写 `myVariable`。
- 以大写字母开头的标识符通常表示**用户自定义类型**，如结构体、类、枚举：`MyClass`。
- 避免不常见的缩写；名字的长度应与它所代表内容的复杂程度成正比。
- 修改已有代码时遵循该代码库的惯例；开发新代码时采用现代最佳实践。

### 6. 字面量

字面量是直接写进源代码里的固定值：

```cpp
std::cout << 5;      // 字面量 5，写在源码里，改不了
int x { 5 };         // 把 5 复制进 x 的内存，运行期间 x 可以改
```

### 7. 字符串、换行与空白

字符串字面量**不能跨行**：

```cpp
std::cout << "Hello
     world!";        // 不允许
```

相邻的字面量会自动拼接：

```cpp
std::cout << "Hello "
              "world!";   // 输出 Hello world!
```

空白字符在代码里会被忽略，所以可以把一行拆成多行：

```cpp
std::cout
    << "Hello world";   // 可以
```

运算符换行时，约定放在下一行的开头：

```cpp
std::cout << 3 + 4
    + 5 + 6
    * 7 * 8;
```

这只是风格约定（learncpp 推荐），不是语法要求。

### 8. 算术运算符与优先级

顺序和数学一致：先括号，再乘除，最后加减。C++ **没有幂运算符**，算幂要用 `std::pow`。

### 9. 双引号与单引号

```cpp
std::cout << "该数的两倍为" << num << "。\n";
```

结束部分用 `"。\n"` 而不是 `'。\n'`：后者是多字符字面量，类型是 `int`、值由实现定义，输出时会变成一串数字。只换行写 `'\n'` 或 `"\n"` 都行。

### 10. 函数的形式

```cpp
returnType functionName()   // 函数头：告诉编译器函数存在
{
    // 函数体：告诉编译器函数做什么
}
```

- C++ **不能嵌套定义函数**，一个函数不能写在另一个函数里。
- 演示用的占位名：`foo`、`bar`、`baz`、`goo`、`moo`、`boo`。

### 11. 返回类型与 main

- `returnType` 声明函数返回什么类型的值。
- `void` 表示不向调用者返回任何值。
- `main` 的返回类型是 `int`，参数列表写成 `()`；C++ 不允许直接调用 `main()`。

### 12. 值返回函数

返回类型不是 `void` 的函数叫**值返回函数**，必须通过 `return` 返回一个该类型的值，否则是未定义行为。

```cpp
int getValueFromUser()
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;
    return input;
}
```

`main` 是例外：省略 `return` 时等价于 `return 0`。

### 13. 只能返回一个值

函数只能返回一个值。要一次返回多个结果，常见做法有三种：

```cpp
struct Pair { int a, b; };
Pair readTwo();

void readTwo(int& a, int& b);

std::tuple<int, int> readTwo();   // C++17 起可 auto [a, b] = readTwo();
```

### 14. DRY：不要重复代码

重复的代码不方便修改，而且冗余，常规做法是抽成函数反复调用。

```cpp
int main()
{
    int x{ getValueFromUser() };
    int y{ getValueFromUser() };

    std::cout << x << " + " << y << " = " << x + y << '\n';
    return 0;
}
```

相比把"提示 + 读入"抄两遍，抽成函数之后，想读第三个数只需要加一行，函数一行都不用改。

### 15. 多个 return

函数执行到**第一个被遇到的 return** 就立刻返回，后面的代码不再执行。

## 二、易错点

下面每条都是当时做错、或者容易想当然的地方。解释尽量写透：错在哪、为什么错、正确的认识、边界在哪。

### 1. 未初始化变量没有"默认值"

**易错点**：以为"没写初始化，变量会拿到一个默认值，哪怕是垃圾值"。

```cpp
int x;
std::cout << x;   // 未定义行为

int d{};
std::cout << d;   // 0
```

**错在哪**：把"未初始化"理解成"值恰好是内存里剩下的东西"。按这个想法，你会觉得至少能读到一个数，只是不确定；实际上标准连"能读到什么"都不保证，编译器甚至可以优化掉这段代码。

**为什么**：对象在定义时没有写入任何值，它就不处于"有值"的状态。C++ 为了性能不会替局部变量清零；读取这种对象属于未定义行为，编译器可以假设它不会发生。

**正确认识**：未初始化对象没有值；`int x{};` 才是值初始化，值为 0。

**边界与变体**：全局变量和 `static` 变量会被零初始化；`new int` 不初始化，`new int()` 才初始化为 0。

**怎么用**：局部变量一律写 `{}`；看到裸的 `int x;` 就当成 bug 候选。

### 2. 未定义行为和实现定义行为不是一回事

**易错点**：把两者都当成"编译器各自决定"，于是遇到 UB 也以为"换个编译器试试就好"。

**错在哪**：UB 是"标准不管"，结果没有意义，程序可能崩溃、可能输出乱码、也可能"看起来正常"；实现定义是"标准要求实现决定并写进文档"，结果在该编译器上是确定的。

**为什么**：C++ 标准要同时适配各种平台，对依赖硬件细节的东西（`sizeof(int)`）只规定"由实现决定"；对会妨碍优化的东西（未初始化读取、有符号溢出）直接不给保证，让编译器放手优化。

**正确认识**：UB = 没有保证，必须避免；实现定义 = 有保证但依赖编译器，查文档即可。

**边界与变体**：`sizeof(int)`、多字符字面量的值属于实现定义；未初始化读取、有符号溢出、数组越界属于 UB。

**怎么用**：看到"实现定义"去查文档；看到 UB 就当 bug 修，别拿"在我机器上能跑"当证据。

### 3. 字符串不能跨行，但相邻字面量会拼接

**易错点**：以为换行写在字符串里只是排版问题，或者以为把字符串拆成两段会输出两段。

```cpp
std::cout << "Hello
world!";              // 编译错误

std::cout << "Hello "
             "world!"; // Hello world!
```

**错在哪**：C++ 的字符串字面量必须以引号开头、以引号结尾；中间出现换行会报 `missing terminating " character`（MSVC 是 C2001）。而两个相邻的字面量会被自动拼接，拼接处不会加空格。

**为什么**：拼接是翻译阶段的语言特性；字符串字面量不允许跨行，是为了让词法分析简单确定。

**正确认识**：跨行用 `\n` 或相邻字面量拼接；拼接不会自动补空格。

**边界与变体**：`"Hello "` 和 `"world!"` 拼出来是 `Hello world!`；如果第一段末尾没留空格，就会变成 `Helloworld!`。

**怎么用**：长字符串分多行写时，把空格显式留在上一段末尾。

### 4. `'。\n'` 是多字符字面量

**易错点**：以为单引号里可以放多个字符，或者以为 `'。\n'` 就是"句号加换行"。

**错在哪**：单引号包裹多个字符时，它不是字符串，而是**多字符字面量**，类型是 `int`，值由实现定义。`std::cout << '。\n'` 输出的是一串数字，不是"。"加换行。再加上 `'。'` 在 UTF-8 里本身就占 3 个字节，编译器还可能提示字符常量过长。

**为什么**：`char` 只有一个字节，放不下多个字符；语言允许这种写法只是为了兼容，值怎么算由编译器决定。

**正确认识**：单个字符用 `'x'`，字符串用 `"..."`；多字符的东西一律用双引号。

**边界与变体**：`'\n'` 是单个字符，合法；`"\n"` 是字符串，也合法；`'ab'` 属于实现定义。

**怎么用**：看到单引号里有多个字符，几乎一定是笔误，改成双引号。

### 5. 运算符换行是风格，C++ 也没有幂运算符

**易错点**：以为"运算符必须写在下一行开头"是语法规则；或者把数学里的"指数运算"当成 C++ 的运算符。

**错在哪**：C++ 的 token 不关心换行，`3 + 4 +` 换行接 `5`，和 `3 + 4` 换行接 `+ 5`，都能编译。真正的风险是排版影响可读性，不是编译。另一方面，C++ 没有 `**` 这样的幂运算符，`^` 是按位异或——`2 ^ 10` 等于 8，不是 1024。

**为什么**：空白和换行在 C++ 里只是分隔 token 用的；运算符优先级只由运算符本身决定。幂运算没有专门符号，标准库用函数解决。

**正确认识**：换行位置是风格问题；C++ 的算术运算符只有 `+ - * / %`。

**边界与变体**：`std::pow(2, 10)` 返回浮点数 `1024.0`；`^` 是按位异或。

**怎么用**：跟着项目的格式化风格走；算幂用 `std::pow`，别写 `^`。

### 6. `getValueFromUser()` 一个参数都没有

**易错点**：把"函数返回一个值"和"函数接受一个参数"搞混，以为它有一个参数。

```cpp
int getValueFromUser()   // 括号是空的：0 个参数
{
    int input{};
    std::cin >> input;
    return input;        // 返回 1 个值
}
```

**错在哪**：读代码时容易把 `()` 里的空当成"没说默认有一个"，或者把返回值当成参数。结果写调用时多传一个值就编译失败。

**为什么**：参数列表和返回类型是两件独立的事。`()` 表示不接受参数；`int` 表示返回一个 `int`。这个函数自己从键盘取值，不需要外部传入。

**正确认识**：这个函数 0 个参数、1 个返回值。

**边界与变体**：把返回类型改成 `void`，`return input;` 就会编译报错；`main` 也是 0 个参数（或 `argc, argv` 两个）。

**怎么用**：数括号里的逗号；空括号就是 0 个参数。

### 7. 多个 return：执行到哪个就返回哪个

**易错点**：以为"函数里有多个 return，只会执行最上面的那个"。

```cpp
int f(int x)
{
    if (x > 0)
        return 1;
    return 2;
}
```

**错在哪**：按"最上面"理解，会以为 `f(-5)` 也返回 1。实际 `f(5)` 返回 1，`f(-5)` 返回 2——取决于执行流走到哪一个。

**为什么**：`return` 会立刻结束函数。文本上排在最前面的 return 如果被 `if` 挡住，就不会执行。

**正确认识**：执行到第一个被遇到的 return 就返回，后面的代码再也不执行。

**边界与变体**：`return` 后面的语句是不可达代码，编译器通常会警告；值返回函数如果所有路径都没 return，是未定义行为。

**怎么用**：读函数时按执行路径想，不要按文本顺序数。

### 8. 命名：类型大写，变量和函数小写

**易错点**：觉得命名是个人喜好，随便写。

| 写法 | 判断 |
| --- | --- |
| `my_variable` | 变量，符合 |
| `MyVariable` | 按规范不合适，变量应小写开头 |
| `myclass` | 不符合，类型要大写开头 |
| `MyClass` | 类型，符合 |
| `getValue()` | 函数，符合 |
| `GetValue()` | 不符合，函数应小写开头 |

**错在哪**：不看大小写，读代码时就得靠上下文猜这是变量还是类型；编译器也不会替你检查。

**为什么**：C++ 区分大小写，命名是唯一能让人快速区分"类型 / 变量 / 函数"的线索。

**正确认识**：类型用大写开头（`MyClass`），变量和函数用小写开头；多单词用下划线或驼峰。

**边界与变体**：全大写的标识符通常留给宏和常量；库代码有自己的风格，改旧代码时跟旧代码走。

**怎么用**：新代码按上面的规则；进已有项目先看周围怎么命名。

### 9. 只能返回一个值，有三种绕法

**易错点**：以为可以用"一次返回两个值"的语法，或者想返回一个字典、列表（那是 Python 的思路）。

**错在哪**：C++ 函数签名里的返回类型只有一个，`return a, b;` 里的逗号是逗号运算符，结果只返回 `b`，而且大概率伴随警告。

**为什么**：返回值只有一个位置。要带回多个结果，就把它们打包成一个对象，或者通过引用写出。

**正确认识**：三种常见做法——返回结构体、引用出参、返回 `std::tuple`。

**边界与变体**：返回结构体最直观；出参适合"调用者已有变量要填"；`tuple` 适合临时组合，但字段没有名字。

**怎么用**：两个相关值时优先结构体；调用方已有变量时用引用出参。

## 三、速查

| 场景 | 写法 |
| --- | --- |
| 局部变量初始化 | `int x{};` |
| 只换行 | `'\n'` 或 `"\n"` |
| 长字符串分行 | 相邻字面量拼接，空格留在上一段末尾 |
| 算幂 | `std::pow(base, exp)` |
| 一次返回多个值 | `struct` / 引用出参 / `std::tuple` |
| 数函数参数个数 | 数 `()` 里的逗号 |
