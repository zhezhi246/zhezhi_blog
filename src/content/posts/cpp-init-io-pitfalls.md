今天读的是 learncpp 的入门几节：程序结构、变量与初始化、iostream。按 [学习指南](../learncpp-guide/) 的路线，这部分是第 1–2 章的地基。

## 一、完整笔记

### 1. 第一个程序

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello world!";
    return 0;
}
```

逐行拆开看：

- `#include <iostream>`：预处理指令，在编译前把 `iostream` 库的内容包含进来，后面才能用 `std::cout`、`std::cin`。
- `int main()`：程序入口，操作系统从这里开始执行。
- `std::cout << "Hello world!";`：`cout` 是 character output，`<<` 把右边的数据送进输出流。
- `return 0;`：告诉操作系统程序正常结束。

`std::` 是命名空间前缀，标准库的东西都放在 `std` 这个名字空间里。

### 2. 注释

```cpp
// 单行注释，从 // 到行尾

/*
   多行注释
   可以跨行
*/
```

VS Code 里 `Ctrl + /` 快速切换行注释。

注释应该说明**为什么**要执行某项操作，而不是复述代码在做什么：

```cpp
// 好：说明原因
// 下面必须取绝对值，因为 sqrt 不接受负数
double v = std::abs(raw);

// 差：只是把代码翻译了一遍
// 把 raw 取绝对值
double v = std::abs(raw);
```

### 3. 字符与字符串

- 字符用**单引号**：`'H'`、`'$'`
- 文本用**双引号**：`"Hello"`、`"H"`

| 写法 | 类型 | 含义 |
| --- | --- | --- |
| `'H'` | `char` | 一个字符，本质是整数，`'H'` 的值是 72 |
| `"H"` | `const char[2]` | 字符串字面量：`'H'` 加上结尾的 `'\0'` |

`'H'` 可以直接赋给 `char`；`"H"` 不行，它是数组，会退化成指针。

"单个字符"就是**一个字符**，一个字母、数字、标点、空格都算，和"单词"无关。中文一个汉字在 UTF-8 下是 3 个字节，`char` 放不下，得用 `std::string`。

### 4. 对象与内存

程序里的变量最终都住在内存（RAM）里。C++ 不推荐直接按地址访问内存，而是通过**对象**间接访问：对象是一块有类型、有名字的存储区域。

```cpp
int x = 42;   // x 是一个对象，代表一块能存 int 的存储区域
x = 43;       // 通过对象 x 间接访问那块存储
```

假设 `x` 被放在地址 140 处，每次程序用到 `x`，就去读地址 140 的值。这件事由编译器负责，正常写代码不需要（也不应该）手写地址。

对象的类型必须在**编译期**确定，编译器才能算出它需要多少内存。这也是 C++ 被称为静态类型语言的原因。

### 5. 四种初始化

```cpp
int a = 5;   // 复制初始化 copy-initialization
int b(6);    // 直接初始化 direct-initialization
int c{7};    // 列表初始化 list-initialization（最推荐）
int d{};     // 值初始化 value-initialization（空大括号）
```

- **复制初始化**：理念上效率低于其他写法，已经不再被青睐；
- **直接初始化**：用圆括号；
- **列表初始化**：用花括号，带有编译期检查，最推荐；
- **值初始化**：空花括号，把变量初始化为 0。

`{0}` 和 `{}` 怎么选：确实需要这个初值时用 `{0}`；值只是临时的、将来会被替换时用 `{}`。

在创建变量时，务必对其进行初始化处理。

### 6. 窄化转换

列表初始化不允许**窄化转换**（narrowing）：可能丢精度或装不下的转换，编译器直接报错。

```cpp
int w1 { 4.5 };  // 编译错误：narrowing conversion from double to int
int w2 = 4.5;    // 能编译，w2 被复制初始化为 4
```

- 圆括号和 `=` 不做这个检查，`4.5` 被直接截断成 4（不是四舍五入）；
- 窄化不只是浮点：`double → int`、`long → int`、`int → char` 都算，判据是"可能装不下或丢精度"。

### 7. 一条语句定义多个变量

```cpp
int a, b = 5;      // 错误理解：以为 a 和 b 都是 5
int a = 5, b = 5;  // 正确：两个都是 5
```

`int a, b = 5;` 等价于 `int a; int b = 5;`，`=` 只作用于紧挨着它的那个变量。

### 8. [[maybe_unused]]

变量暂时不用时编译器可能警告。用属性明确表示"我知道它没被用，不用管"：

```cpp
[[maybe_unused]] double gravity { 9.8 };  // 不因为没用到而报警告
```

### 9. 默认初始化与值初始化

- **默认初始化**：`int x;`，没有指定初值。局部变量的值**不确定**，不一定是 0，读它属于未定义行为。
- **值初始化**：`int x{};`，空大括号，值为 0。

建议使用值初始化，保证变量总有一个一致的初值。

### 10. iostream：输入与输出

`io` 就是 input / output。`std::cout` 是 character output，`<<` 和 `>>` 可以想成传送带，把数据按箭头的方向传送。

```cpp
#include <iostream>

int main()
{
    std::cout << "Hi!" << std::endl;               // 换行，光标移到下一行
    std::cout << "My name is Alex." << std::endl;
    return 0;
}
```

`std::endl` 是 end line，输出换行并把光标移到下一行。

### 11. 缓冲区与 endl 的代价

`cout` 的输出不会立刻送到控制台，而是先进入**缓冲区**，隔一段时间整体发送出去。

`std::endl` 实际上执行两项操作：

1. 输出换行符 `'\n'`；
2. 刷新（flush）缓冲区。

flush 要把数据真正交给终端或磁盘，比较耗时，所以频繁使用 `std::endl` 会明显拖慢程序。只要换行的话，用 `'\n'`：

```cpp
std::cout << "hello\n";   // 只换行，不刷新缓冲区
```

`'\n'` 是字符，`"\n"` 是字符串，写进输出流都能换行。

### 12. cin 与输入缓冲区

```cpp
#include <iostream>

int main()
{
    std::cout << "Enter two numbers: ";

    int x{};
    std::cin >> x;

    int y{};
    std::cin >> y;

    std::cout << "You entered " << x << " and " << y << '\n';
    return 0;
}
```

输入缓冲区里的每一行都以 `'\n'` 结尾。`std::cin >> x` 会等待用户输入，用户敲的整行先进缓冲区，`>>` 再按类型从里面提取。

几种输入的实际表现：

| 输入 | 缓冲区 | 第一次提取 | 第二次提取 |
| --- | --- | --- | --- |
| `4` | `4\n` | `x = 4` | 等待新输入 |
| `4 5` | `4 5\n` | `x = 4`（遇空格停） | 不等待，`y = 5` |
| `abc` | `abc\n` | 失败，`x = 0` | 立刻失败，`y = 0` |
| `3.2` | `3.2\n` | `x = 3`（遇 `.` 停） | 失败，`y = 0` |
| `-3` | `-3\n` | `x = -3` | 等待新输入 |

提取规则：

1. 先跳过前导空白（空格、`\t`、`\n`）；
2. 按目标类型读：读 `int` 时只接受数字和开头的一个 `+` / `-`；
3. 遇到不属于该类型的字符就**停下**，这个字符**留在缓冲区**；
4. 一个合法字符都没读到 → 失败：C++11 起变量被置为 **0**，并设置 failbit；此后所有 `cin >>` 都会立刻失败，要先 `cin.clear()` 才能恢复。

窄化转换只在列表初始化（花括号）里被禁止，`cin` 的提取不受这个规则限制，所以往 `int` 里读 `3.2` 会截断成 3。

## 二、易错点

下面每条都是当时做错、或者容易想当然的地方。解释尽量写透：错在哪、为什么错、正确的认识、边界在哪。

### 1. `int x;` 是默认初始化，值不确定，不是 0

**易错点**：以为"变量没写初始化，值就是 0"。

```cpp
int d{};          // 值初始化：d 一定是 0
int x;            // 默认初始化：值不确定
std::cout << x;   // 可能是 0，也可能是任意值
```

**错在哪**：按"不写就是 0"的想法写代码，就会省略初始化。测试时很可能刚好跑通——局部变量所在的栈内存上一次恰好是 0；换一台机器、换一个优化等级，同样的代码就输出随机数。这不是"0 偶尔不对"，而是结果从一开始就没有保证。

**为什么**：局部变量分配在栈上，栈空间是复用的，上一轮函数调用留下的数据还在原处，所以 `int x;` 拿到的就是那块内存的残留。C++ 为了性能不会主动清零（清零意味着每次进函数都要写一遍内存），标准干脆把读取未初始化变量定为**未定义行为**（undefined behavior）。未定义行为不是"某个固定的垃圾值"，而是编译器可以假设这件事不会发生，进而做出任何优化。

**正确认识**：默认初始化只保证"对象存在、类型确定"，不保证值；值初始化 `{}` 才保证为 0。**"未初始化"和"值为 0"是两件事。**

**边界与变体**：

- 全局变量和 `static` 变量有静态存储期，会被零初始化。同一句 `int x;` 放进全局作用域就"正常"了，很容易让人误以为规则一致。
- `int x = 0;` 是复制初始化，也得到 0，但语义和值初始化不同（对类类型尤其明显）。
- `new int` 是默认初始化（不确定值），`new int()` 才是值初始化（0）。

> [!WARNING]
> 编译器通常不会对"读了未初始化变量"报错，`-Wall` 也只能发现部分场景。这条只能靠自己养成习惯。

**怎么用**：声明局部变量时一律给初值，优先写 `int x{};`；代码里看到裸的 `int x;` 就当成 bug 候选。

### 2. `int x, y = 5;` 只初始化了 `y`

**易错点**：以为一行里写了 `= 5`，`x` 和 `y` 就都是 5。

```cpp
int x, y = 5;      // 等价于 int x; int y = 5; —— x 仍未初始化
int x = 5, y = 5;  // 正确：两个都是 5
```

**错在哪**：在 Python 里 `x = y = 5` 是链式赋值，两个都变 5；把这个直觉带到 C++，就会以为 `int x, y = 5;` 同理。实际跑起来 `y` 是 5，`x` 是未初始化的随机值，而且编译器通常不报错。

**为什么**：C++ 的声明语法是"一个类型说明符 + 一串声明符"，`int x, y = 5;` 拆开是两个独立的声明符：`x` 和 `y = 5`。初始化器 `= 5` 只属于它所在的那个声明符，不会分给前面的变量。

**正确认识**：逗号分隔的是**声明符**，不是赋值语句；每个变量要各自带初始化器。

**边界与变体**：

- `int x, *p = &x;` 语法合法，但 `p` 指向的 `x` 还没初始化，解引用 `*p` 同样是未定义行为。
- `int a{}, b{};` 两个都值初始化为 0，是最省事的安全写法。

**怎么用**：一行只声明一个变量，或者每个变量都带上 `{}`。

### 3. 窄化转换只在花括号里被禁止

**易错点**：以为"C++ 会阻止所有精度损失"，或者以为圆括号初始化也有同样的检查。

```cpp
int a { 4.5 };   // 编译错误：narrowing conversion from 'double' to 'int'
int b = 4.5;     // 能编译，b == 4（截断，不是四舍五入）
int c ( 4.5 );   // 能编译，c == 4
```

**错在哪**：看到花括号报错，就以为 C++ 对窄化是全面禁止的；换成 `=` 或 `()` 之后编译通过，又以为"这样写就没问题"。实际上 `b` 和 `c` 悄悄丢了 0.5，编译器一声不吭。

**为什么**：窄化检查是**列表初始化**独有的规则。花括号初始化在设计上被当作"统一、安全"的初始化语法，所以编译器在里面做编译期检查；`=` 和 `()` 是历史遗留写法，为了兼容 C 语言允许隐式转换。窄化也不止浮点：`double → int`、`long → int`、`int → char`，凡是目标类型可能表示不了源值的转换都算。

**正确认识**：只有花括号会拦窄化；圆括号和 `=` 会静默截断。

**边界与变体**：

- `int x{4}` 可以，int 常量 4 在 int 范围内。
- `int x{4.0}` 不行：只要源类型是浮点、目标是整数，即使值恰好是整数也禁止。
- `char c{300}` 不行，300 超出 `char` 的范围；`unsigned u{-1}` 也不行。
- `std::cin >> x` 不受这个规则约束，所以运行时能往 `int` 里读进 `3.2` 并截断成 3。

**怎么用**：新代码统一用 `{}` 初始化，让编译器帮你抓窄化；确实想截断就写 `static_cast<int>(4.5)`，把意图显式写出来。

### 4. `char c = "H";` 编译不过

**易错点**：以为单引号和双引号可以互换，或者以为 `"H"` 就是"字符 H"。

```cpp
char c = 'H';        // 正确：char
char bad = "H";      // 编译错误：invalid conversion from 'const char*' to 'char'
std::string s = "H"; // 正确：字符串
```

**错在哪**：把 `"H"` 当成一个字符。编译器报的是指针转 `char` 的错误，信息看起来和"引号写错"没直接关系，容易让人以为是自己漏了 `*` 或写错了类型。

**为什么**：单引号包裹的是一个 `char`，本质是小整数，`'H'` 的值是 72。双引号包裹的是字符串字面量，类型是 `const char[2]`——`'H'` 加结尾的 `'\0'`。数组在参与赋值时会退化成指向首字符的指针 `const char*`，指针塞不进一个字节的 `char`，于是编译失败。

**正确认识**：`'H'` 是字符，`"H"` 是字符串；两者类型不同，不能混用。

**边界与变体**：

- `"H"` 的 `sizeof` 是 2，不是 1。
- `'ab'` 这种多字符字面量语法上合法，但值由编译器实现定义，标准不保证，别用。
- 中文一个汉字在 UTF-8 下占 3 个字节，单个 `char` 放不下，要用 `std::string`。

**怎么用**：需要单个字符用单引号，需要一串字符用双引号；`char` 只放 ASCII 范围内的一个字符。

### 5. `std::endl` 比 `'\n'` 慢

**易错点**：以为 `endl` 只是"换行"的另一种写法，和 `'\n'` 差不多，随手就用。

```cpp
for (int i = 0; i < 100000; ++i)
    std::cout << i << std::endl;   // 每行都 flush，很慢
```

**错在哪**：小数据量下看不出区别，一旦放进循环，程序就慢得明显；而且这种慢很难归因到 `endl` 上，容易怀疑是别的地方。

**为什么**：`std::endl` 做两件事——输出 `'\n'`，然后 **flush 缓冲区**。`cout` 平时是带缓冲的，先把输出攒在用户态内存里，攒够了或程序退出时再一次性交给系统。flush 会强制立刻把缓冲区交给内核和终端，相当于每行触发一次系统调用级的操作。十万次循环就是十万次 flush，和"攒着一次写出"根本不是一个数量级。

**正确认识**：`endl` = 换行 + 刷新；`'\n'` 只换行。日常输出用 `'\n'`。

**边界与变体**：

- 程序正常退出时缓冲区会自动刷新，所以不用 `endl` 也不会丢输出。
- `std::cin` 读输入前会自动刷新 `cout`（两者默认绑定），所以"先输出提示再读输入"不需要手动 flush。
- 调试时情况反过来：程序崩溃时缓冲区里没刷出的内容会丢，看起来像"这行没执行"；这时用 `endl` 或 `std::flush` 更可靠。
- `std::cerr` 是无缓冲的，写进去立刻出现，代价同样更慢。

**怎么用**：常规输出用 `'\n'`；需要立刻看到（调试、进度条）再用 `endl` 或 `flush`。

### 6. `cin >>` 停在哪、失败了会怎样

**易错点**：以为第二次 `cin >>` 一定会停下来等输入；以为输入 `abc` 会让程序卡住；以为 `3.2` 会被四舍五入，或者干脆报错。

```cpp
int x{}, y{};
std::cin >> x;   // 输入 3.2
std::cin >> y;   // 不会等待，y == 0
```

**错在哪**：把 `cin >>` 当成"读一整行再转换"。实际上它只消费自己能解析的部分，剩下的字符留在缓冲区里，影响下一次读取。所以 `3.2` 会把 `x` 读成 3，而下一个 `int` 提取撞上 `.`，直接失败——程序不会等用户重新输入，而是继续往下跑，`y` 变成 0。

**为什么**：`>>` 对目标类型做词法解析。`int` 的合法字符集是数字和开头的一个 `+` / `-`；读到一个不属于这个集合的字符就停，那个字符留在缓冲区。一个合法字符都没读到就是提取失败：C++11 起变量被置为 0，同时流设置 failbit。一旦 failbit 置位，后续所有 `cin >>` 都会立刻返回失败，不消耗任何输入，也不再等待——所以程序看起来"跳过"了后面所有输入。

**正确认识**：`>>` 是按类型提取，不是按行读取；失败会粘住整个流，直到 `cin.clear()`。

**边界与变体**：

| 输入 | 第一次 | 第二次 | 说明 |
| --- | --- | --- | --- |
| `4 5` | x = 4 | y = 5 | 空格是分隔符，被跳过 |
| `abc` | x = 0 | y = 0 | 第一个字符就不合法 |
| `3.2` | x = 3 | y = 0 | 停在 `.`，`.` 对 int 非法 |
| `-3` | x = -3 | 等待 | `-` 是合法符号 |
| `0x10` | x = 0 | y = 0 | 按十进制只读 0，停在 `x` |

**怎么用**：

- 交互式输入要检查结果：`if (!(std::cin >> x)) { ... }`。
- 失败后先 `std::cin.clear()` 清状态，再用 `std::cin.ignore(...)` 丢掉缓冲区里的坏字符，否则下一次读取还是立刻失败。
- 需要整行读取时用 `std::getline`，不要拿 `>>` 硬凑。

## 三、速查

| 场景 | 写法 |
| --- | --- |
| 想要 0 | `int x{};` |
| 声明多个变量并都初始化 | `int a{}, b{};` |
| 只要换行 | `'\n'` |
| 要立刻显示 | `std::endl` 或 `std::flush` |
| 提取失败后恢复 | `std::cin.clear();` |
