今天读的是函数相关的内容：void 函数、按值传递、局部变量和生命周期、临时对象、前置声明、ODR，最后落到命名空间。笔记里大部分是 learncpp 的整理，**加粗的部分是我自己写的理解或补充**。

## 一、完整笔记

### 1. void 函数：不返回值

一个不返回值的函数叫非返回值函数，也叫空函数（void function）。

```cpp
void printHello()
{
    std::cout << "Hello!\n";
}
```

void 函数里可以写 `return;`，但不带返回值，而且通常多余。写 `return 0;` 会编译错误，因为 void 函数不能返回值。

void 函数不能用在需要值的地方。比如 `std::cout <<` 的右边需要一个值：

```cpp
// std::cout << printHello(); // compile error: no value provided
```

`printHello()` 的结果是“空”，不能作为 `<<` 的操作数。

### 2. 按值传递：参数是复制进来的

调用函数时，每个参数都会被创建成一个变量，实参的值通过复制初始化传给形参。这种传递方式叫按值传递，这样的参数叫值参数。

```cpp
void addOne(int x)
{
    ++x;
}

int main()
{
    int a{5};
    addOne(a);
    std::cout << a << '\n'; // 5
}
```

**我的理解：按值传递就是“复印一份进去”，函数里改的是复印件，原件不动。**

如果希望函数修改外面的变量，可以用引用 `int&` 或指针；如果只是读取大对象，用 `const&` 避免复制。

### 3. 未使用的参数

如果某个参数在函数体里用不到，可以只写类型、不写名字：

```cpp
void doSomething(int) // 不命名，就不会有“未使用参数”的警告
{
}
```

如果写成 `void doSomething(int count)` 但函数体里不用 `count`，编译器会警告未使用参数。两种写法是二选一，不要同时写。

保留参数但不命名，通常是为了向后兼容：函数以前用过这个参数，后来不用了，但不想破坏现有调用方。也可以在注释里保留名字：

```cpp
void doSomething(int /*count*/)
{
}
```

**我的理解：参数不用就别起名字，编译器就不会警告；如果为了兼容旧代码不能删参数，就写 `int /*count*/` 保留说明。**

### 4. 局部变量、生命周期与作用域

定义在函数体内的变量叫局部变量。函数参数通常也算局部变量。

局部变量的销毁顺序和创建顺序相反；函数参数在函数执行完毕时销毁。

```cpp
void doSomething()
{
    std::cout << "Hello!\n";
}

int main()
{
    int x{0};       // x 的生命周期从这里开始

    doSomething();  // 调用 doSomething 时，x 还活着

    return 0;
} // x 的生命周期到这里结束
```

`x` 的生命周期从定义点开始，到 `main` 执行完毕为止，包括 `doSomething()` 执行的那段时间。对象被销毁后，再对它做任何操作都是未定义行为。

作用域是“名字能看见的范围”：从定义点开始，到包含它的最内层花括号结束。对象在作用域末尾“超出作用域”。

生命周期和作用域不是一回事：

- 生命周期是运行时属性：对象什么时候真正创建、什么时候真正销毁；
- 作用域是编译时属性：名字在源代码的哪个区域可见。

**我的理解：作用域是“名字能看见的范围”，生命周期是“对象真正活着的时间”。大多数局部变量两者一起结束，但 `static` 局部变量是例外：名字出了花括号就看不见，对象还在。**

另外，并不是所有变量在超出作用域时都会被销毁。`static` 局部变量的作用域在块内，但生命周期是整个程序；动态分配的对象则要等到 `delete` 才销毁。

函数调用里的参数也是局部变量：

```cpp
int add(int x, int y) // x、y 在这里创建并进入作用域
{
    return x + y;
} // y、x 在这里超出作用域并销毁

int main()
{
    int a{5};
    int b{6};
    std::cout << add(a, b) << '\n'; // x=5, y=6
    return 0;
}
```

`x` 和 `y` 在每次调用 `add` 时都会重新创建、重新销毁。`main` 里的 `a`、`b` 和 `add` 里的 `x`、`y` 是不同作用域里的不同变量，即使名字改成一样也没有关系。

### 5. 临时对象

```cpp
int getValueFromUser()
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;
    return input;
}

int main()
{
    std::cout << getValueFromUser() << '\n';
    return 0;
}
```

`input` 在 `getValueFromUser` 里创建，返回后 `main` 并没有变量接住它。返回值被存进一个临时对象，然后这个临时对象被传给 `std::cout`。

临时对象没有作用域。它在创建它的整个表达式执行完毕时销毁，也就是说，总是在下一条语句执行之前被清除。

**我的理解：`input` 在函数里创建，返回后 `main` 没有变量接住它；返回值先放进一个临时对象，再传给 `std::cout`。临时对象没有作用域，整个表达式结束就销毁。**

### 6. 什么时候该写函数

一些常见的判断标准：

- 多次出现的语句组，通常应该整理成函数；
- 有明确输入和输出的代码，适合写成函数，尤其是逻辑比较复杂的时候；
- 一个函数通常只做一件事，比如“算数值”和“打印结果”最好分开；
- 函数太长、太复杂、难以理解时，可以拆成多个子函数。

一个典型的小程序结构是：读取用户输入 → 根据输入计算 → 打印结果。把这三步拆成函数，主函数会清楚很多。

### 7. 前置声明与定义

编译器按顺序处理代码，所以调用一个还没定义的函数会编译错误。解决办法是把函数定义移到前面，或者先写函数声明：

```cpp
int add(int x, int y); // 前置声明

int main()
{
    std::cout << add(3, 4) << '\n';
    return 0;
}

int add(int x, int y) // 真正的定义在后面
{
    return x + y;
}
```

函数声明不需要参数名，`int add(int, int);` 也可以；但写上参数名更方便对照。

声明和定义的区别：

- 声明告诉编译器“这个名字存在，类型是什么”；
- 定义提供实体，比如函数体、变量的存储。

在 C++ 里，所有定义同时也是声明，所以 `int x;` 既是定义也是声明；但并非所有声明都是定义，比如 `int add(int, int);` 只是声明。

如果只声明、不调用，程序可以编译运行。如果声明了、也调用了，但没有定义，程序能编译通过，链接器会报错，提示找不到函数定义。

### 8. 单一定义规则（ODR）

ODR 的核心是：在一个程序中，给定作用域内的每个函数、变量、类型或模板只能有一个定义。

```cpp
int add(int x, int y)
{
    return x + y;
}

int add(int x, int y) // 违反 ODR：add(int, int) 已经定义过
{
    return x + y;
}

int main()
{
    int x{};
    int x{5}; // 违反 ODR：x 已经定义过
}
```

同一个文件里重复定义，通常是编译错误；不同文件里出现同名函数或全局变量，通常是链接错误。

类型、模板、内联函数和内联变量是例外：它们在不同文件里可以有重复定义，只要每个定义完全相同。

**我的理解：头文件里直接写函数定义，被两个 `.cpp` 包含，就会各编译出一份，链接时重复定义；头文件只放声明。**

### 9. 命名冲突、作用域与命名空间

命名冲突有两种常见情况：

- 不同文件里引入了同名的函数或全局变量，链接器报错；
- 同一个文件里引入了同名的函数或全局变量，编译器报错。

作用域是源代码中的一个区域，在这个区域里声明的标识符和其他作用域里的同名标识符被视为不同。两个同名标识符可以在不同作用域里共存，但在同一个作用域里必须唯一。

函数体就是一个作用域，所以两个函数里可以各自定义同名的局部变量。命名空间则是一个“有名字的作用域”，把一组名字包起来，避免和外面的名字冲突。

没有写在类、函数或命名空间里的名字，属于全局命名空间。全局作用域里的标识符从声明点一直可见到文件末尾。虽然可以在全局命名空间定义变量，但通常应该避免。

```cpp
void foo();    // 可以：函数前置声明
int x;         // 可以编译，但不推荐：非 const 全局变量
int y{5};      // 可以编译，但不推荐

// x = 5;      // 编译错误：命名空间里不允许可执行语句

int main()
{
    return 0;
}
```

**我的理解：全局作用域只能放声明/定义，不能放 `x = 5;` 这种执行语句。**

`::` 是作用域解析运算符。`std::cout` 表示“命名空间 `std` 里的 `cout`”。如果 `::` 左边没有名字，表示全局命名空间。

**我的理解：`namespace` 和 Python 的包很像，先指定包，再调用里面的函数；`numpy.arange()` 换到 C++ 就是 `numpy::arange()`。`#include` 更像“把源码拿过来”，`using namespace std;` 相当于 `import numpy`，`using std::cout;` 相当于 `from numpy import array`。不过 `#include` 是文本替换，不是 Python 那种模块导入，这一点后面再说。**

这个类比帮助记忆就好，别把它当成完全等价：`#include` 会把头文件内容原样插入当前文件，`using` 只是让名字可见，并不会“加载”任何定义。

## 二、易错点

### `void` 函数不能拿来取值

我一开始觉得 `std::cout << printHello();` 应该能打印点什么，结果编译不过。

`void` 的意思是“没有类型/没有值”。`printHello()` 只产生副作用（往屏幕输出），它本身不是一个值，所以不能放在 `<<` 右边。void 函数里写 `return;` 是可以的，但没必要；写 `return 0;` 会直接编译错误。

需要结果的时候就让函数返回值；只需要副作用（打印、修改引用参数、写文件）的时候才用 void。

### 按值传递改的是副本

```cpp
void addOne(int x) { ++x; }

int main()
{
    int a{5};
    addOne(a);
    // a 还是 5
}
```

参数 `x` 是调用时新创建的局部变量，实参 `a` 的值被复制进去。函数里改 `x`，改的是这份副本，`a` 不受影响。

想让函数改到外面的变量，参数要写成引用 `int&` 或指针；如果只是读取大对象，用 `const int&`，既避免复制又防止误改。

### 生命周期和作用域不是一回事

```cpp
int* makeLocal()
{
    int x{5};
    return &x; // 返回后 x 已经销毁
}
```

`x` 的作用域到函数末尾结束，生命周期也在函数返回时结束。函数返回后，指针指向的是一块已经失效的内存，再解引用就是未定义行为。

作用域是编译时概念，生命周期是运行时概念。大多数自动变量两者一起结束，但 `static` 局部变量是例外：它的名字只在块内可见，对象却活到程序结束。动态分配的对象也是，作用域结束了，堆上的对象还在，直到 `delete`。

写代码时记住一条：不要返回局部变量的指针或引用；需要跨函数保留对象，就用返回值、容器、智能指针或 `static`。

### 前置声明能让编译通过，但不保证链接通过

```cpp
int add(int x, int y); // 声明

int main()
{
    std::cout << add(3, 4) << '\n';
    return 0;
}
```

如果只写了这一份声明，没有 `add` 的定义，编译器能过，链接器会报 `undefined reference to add(int, int)`。

声明只告诉编译器“有这么个函数”，定义才提供函数体。看到“undefined reference”时，先检查定义是否存在、源文件有没有参与编译和链接。

### 头文件里定义函数会导致重复定义

如果头文件里直接写：

```cpp
int getSquareSides() { return 4; }
```

然后 `a.cpp` 和 `b.cpp` 都 `#include` 这个头文件，两个翻译单元就各有一份 `getSquareSides` 的定义，链接时违反 ODR，报 multiple definition。

头文件应该只放声明；函数定义放到 `.cpp` 里。类型、模板、内联函数/变量是例外，它们可以在头文件里定义，但要有相应的 `inline` 或模板语义。

### `using namespace std;` 放在头文件会污染所有包含者

头文件里写 `using namespace std;`，所有包含这个头文件的 `.cpp` 都会把 `std` 里的名字倒进全局作用域。结果可能是：

- 你自己的 `count`、`distance`、`data` 和标准库的名字撞车；
- 你在全局定义了一个叫 `std` 的变量或函数，和命名空间 `std` 冲突；
- 别人包含你的头文件后，原本能编译的代码突然歧义。

在 `.cpp` 里也尽量少用，非要用就限制在很小的作用域，或者只写 `using std::cout;` 这种精确引入。头文件里一律写 `std::`。

### 命名空间像 Python 的包，但 `#include` 不是 `import`

**我的理解：`namespace` 和 Python 的包很像，先指定包，再调用里面的函数；`numpy.arange()` 换到 C++ 就是 `numpy::arange()`。`#include` 更像“把源码拿过来”，`using namespace std;` 相当于 `import numpy`，`using std::cout;` 相当于 `from numpy import array`。**

这个类比只适合记“名字要带前缀”这一层。真正的区别是：

- `#include` 是预处理阶段的文本替换，会把头文件内容原样插进来；
- Python 的 `import` 是模块加载，不会把源码文本复制到当前文件；
- `using namespace` 不会引入任何定义，只是让已经可见的名字不用写前缀；
- 因为 `#include` 是文本替换，头文件里放定义就可能违反 ODR，Python 里一般不会遇到这种问题。

所以写 C++ 时，看到 `#include` 要想“复制粘贴”，看到 `using` 要想“少写前缀”，不要真的把它当成 Python 的 import。

## 速查表

| 想做的事 | 写法 |
| --- | --- |
| 不返回值的函数 | `void f()` |
| 修改调用方变量 | `void f(int& x)` |
| 只读大对象 | `void f(const Big& x)` |
| 前置声明 | `int add(int, int);` |
| 命名空间限定 | `std::cout` |
| 精确引入一个名字 | `using std::cout;` |
